## ADR-2. Выбор технологии компьютерного зрения для анализа поведения экзаменуемого

### Контекст

Платформа онлайн-прокторинга должна автоматически выявлять подозрительные действия экзаменуемого во время сдачи экзамена.

По требованиям системы необходимо определять:

* присутствие пользователя в кадре;
* появление второго человека;
* использование телефона или других запрещённых устройств;
* направление взгляда;
* положение головы;
* попытки покинуть рабочее место;
* базовые поведенческие аномалии.

Ключевые требования для данного решения:

* **NFR-12**: точность античита — **f1-score ≥ 85%**, что требует раздельного применения специализированных детекторов для разных классов нарушений.
* **SR-SYS-27**: при массовом поступлении событий система агрегирует их, оценивает уровень риска и формирует приоритизированную очередь для проктора.
* **SR-SYS-33**: администратор может изменять параметры античита; изменения должны фиксироваться, валидироваться и гарантированно доставляться в сервис.

Проблема в том, что одна модель плохо решает все задачи одновременно: object detection, pose estimation, face landmarks и gaze tracking требуют разных подходов.

---

### Рассматриваемые варианты

1. Только YOLO-family detector
2. Только MediaPipe
3. OpenPose
4. Комбинированный подход (MediaPipe + lightweight YOLO-family detector)

---

### Решение

Используем **комбинированный подход: MediaPipe + YOLOv8n**.

Где:

* **MediaPipe** отвечает за:

  * landmarks лица;
  * положение головы;
  * gaze estimation;
  * определение моргания;
  * анализ позы.

* **YOLOv8n** отвечает за:

  * обнаружение второго человека;
  * обнаружение телефона;
  * обнаружение наушников;
  * обнаружение посторонних предметов;
  * анализ сцены.

Результаты работы моделей объединяются через **score-level fusion** с вычислением общего risk score как взвешенной суммы выходных значений детекторов.

---

### Обоснование

| Критерий             | Только YOLO | Только MediaPipe | OpenPose | Hybrid |
| -------------------- | ----------- | ---------------- | -------- | ------ |
| Обнаружение объектов | Да          | Нет              | Нет      | Да     |
| Face landmarks       | Ограниченно | Да               | Нет      | Да     |
| Gaze estimation      | Слабо       | Да               | Нет      | Да     |
| Pose estimation      | Средне      | Да               | Да       | Да     |
| CPU friendly         | Да          | Да               | Нет      | Да     |
| Простота интеграции  | Да          | Да               | Средне   | Средне |

Факторы выбора hybrid подхода:

1. **MediaPipe лучше решает задачу анализа лица.**
   Для оценки взгляда, положения головы и моргания нужна высокая точность facial landmarks. MediaPipe решает это лучше object detector-моделей.

2. **YOLOv8n лучше решает задачу обнаружения объектов.**
   Телефон, второй человек и посторонние предметы — классическая задача object detection. YOLOv8n выбран как оптимальный вариант по соотношению скорость/точность на CPU: inference < 30 мс на кадре 720p при 4 CPU-ядрах на референсном сервере (4 vCPU, 8 ГБ RAM).

3. **OpenPose слишком тяжёлый.**
   Модель требует больше вычислительных ресурсов и не укладывается в требование NFR-7 без GPU.

4. **Hybrid подход даёт лучшую расширяемость.**
   Можно независимо улучшать object detector и face/pose pipeline, а также независимо заменять модели при смене требований (SR-SYS-33).

5. **Score-level fusion делает систему explainable.**
   Каждый детектор возвращает собственный confidence score:

   * `gaze_score`
   * `phone_prob`
   * `second_person_prob`
   * `head_rotation_score`
   * `audio_score` *(требует отдельного аудиопайплайна)*

   После чего вычисляется общий risk score как взвешенная сумма признаков. Это позволяет объяснить проктору, почему система отметила попытку нарушения, и служит основой для приоритизации очереди инцидентов (SR-SYS-27).

   > ⚠️ На этапе MVP веса подбираются вручную. Финальная калибровка — на основе размеченного датасета (≥ 1000–2000 сессий) с расчётом precision, recall, f1-score в соответствии с NFR-12.

6. **Целевые показатели производительности.**
   Референсная конфигурация: 4 vCPU, 8 ГБ RAM, без GPU.
   Целевые значения для pipeline MediaPipe + YOLOv8n:

   * inference ≤ 30 мс/кадр при 720p;
   * ≥ 10 FPS устойчиво при типовой нагрузке;
   * событие → уведомление проктору ≤ 5 с в p95 (NFR-7).

---

### Последствия

Позитивные:

* высокая скорость inference; соответствие NFR-7 на CPU;
* хорошее качество детекции; путь к f1 ≥ 85% (NFR-12);
* работает на CPU без GPU;
* модульная архитектура; детекторы заменяются независимо;
* легко расширять новыми детекторами;
* explainable scoring; поддерживает SR-SYS-27.

Негативные:

* нужно поддерживать две ML-модели вместо одной;
* появляется этап score-level fusion;
* веса risk scoring требуют ручной настройки на MVP с последующей калибровкой;
* inference pipeline становится сложнее в части оркестрации;
* `audio_score` в формуле риска предполагает наличие аудиопайплайна;
* необходима проверка работы MediaPipe в условиях плохого освещения и частичного перекрытия лица (очки, маски) — предусмотреть fallback для низко-confidence кадров.
