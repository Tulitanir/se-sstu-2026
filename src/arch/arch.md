## Описание компонент, их обязанности и взаимодействие
### 1. Сервер Прокторинга
#### Компоненты
1. Proctoring  API - API для взаимодейтсвия с сервером
2. Anticheat Handler - Производит обработку событий о действиях экзаменуемых внутри системы путем классификации действий по степени подозрительности или на факт нарушения с учетом актуальных настроек прокторинга
3. Stream Handler - Произоводит анализ поступающего видео потока, публикует события для проктора
4. Archive Manager - Производит агрегацию полученных материалов (видео, обработанные античитом события, события в медиапотоках)
5. Settings Handler - Принимает и записывает настройки для прокторинга
6. SFU Controller - Компонент управления подключения к медиапотокам
#### Взаимодействия
1. Stream Handler, Archive Manager и Proctoring API запрашивают у SFU Controller доступ к нужным видеопотокам
2. SFU Controller делает запросы на инициализацию подключений и сами подключения к SFU
3. Stream Handler читает актуальные настройки из хранилища актуальных настроек прокторинга
4. Stream Handler публикует обнаруженные события в очередь Raw Stream Events
5. Anticheat Handler читает актуальные настройки из хранилища актуальных настроек прокторинга
6. Anticheat Handler анализирует события действий пользователя к экзаменационном приложении из очереди Raw User System Events
7. Anticheat Handler публикует обнаруженные события в очередь Anticheat Events
8. Archive Manager агрериует получаемые медиапотоки, события античита и события медиа, и сохраняет их в российском облачном хранилище
9. Proctoring API осуществляет запрос на получение  подключения к медиапотоку для анализа проктором
10. Proctoring API обращается к SFU Controller для получения подключения видеопотока для проктора
11. Proctoring API принимает запросы на установление Websockets соединения
12. Proctoring API отправляет сообщения для проктора в Web App через Websockets соединение, полученные от Raw Stream Events
13. Proctoring API отправляет сообщения для проктора в Web App через Websockets соединение, полученные от Anticheat Events
14. Proctoring API принимает запрос на фиксацию события и публикует его в Proccessed Stream Events
15. Proctoring API отправляет сообщения для студента в Desktop App Websockets соединение, полученные от Proccessed Proctoring Events
16. Proctoting API принимает запрос на публикацию события действия пользователя в системе, и помещает его в Raw User System Events
17. Settings Handler получает сообщения из очереди Settings и вносит изменения в хранилище актуальных настроек
18. Settings Handler отправляет сообщения в очереди Response для подтверждения применения настроек
19. Proctoring API принимает запрос о получении локальных записей (в случае недоступности ранее), и делегирует задачу сохранения Archive Manager'у
#### Ответственные
За сервер прокторинга отвественная команда разработчиков А, в частности Backend Python Developers, ML Engineer, Testers

### 2. Основной Backend
#### Компоненты
1. Rest API entrypoint - API для взаиможейтсвия с Backend
2. Policy Manager - компонент для работы с историей настроей прокторинга
3. Education Manager - компонент для организации, курсов, заданий, расписания
4. Auth Manager - компонент, отвечающий за аутентификацию и авторизацию
5. Conflict Resolution Manager - компоненет, отвечающий за аппеляционный процесс или оффлайн-прокоторинг
#### Взаимодействия
1. Rest API entrypoint может принимать запрос на изменение настроек проктроинга и делеигировать эту задачу Policy Manager
2. Rest API entrypoint может принимать запрос на получение информации о курсе, задании, расписании и делегировать эту задачу Education  Manager
3. Rest API entrypoint может принимать запрос на аутентификацию и/или авторизацию и делегировать эту задачу Auth Manager
4. Rest API entrypoint может принимать запрос на процедуру апелляции и делегировать эту задачу Conflict Resolution Manager
5. Education Manager выполняет хранение дополнительных сведений об образовательном процессе в Course Database и взаимодействует с LMS
6. Auth Manager хранит информацию об активных сессиях в Redis Cache.
7. Policy Manager ведет историю настроек прокторинга в Proctoring Settings Database
8. Policy Manager публикует события об изменении настроект прокторинга в очередь Settings
9. Policy Manager получает сообщения об изменении настроек сервером прокторинга из очереди Response
10. Conflict Resolution Manager использует историю настроек прокторинга из Proctoring Settings Database для сопоставления с событиями в случае оффлайн-прокторинга
11. Conflict Resolution Manager использует медиа, запрашивая из российского облачного хранилища
#### Ответственные
За Основной Backend отвественна команда разработчиков Б, в частности Backend Go Developers, Testers

### 3. Desktop-приложение по проведению экзаменов
#### Компоненты
1. Streaming Service - модуль фиксации медиапотоков и организации их перессылки
2. Action Inspector Service - модуль фиксации событий действия пользователя в системе
3. Exam Service - сервис орагнизации экзамена
4. UI Layer - интерфейс взаимодейтсвия пользователя и системы
#### Взаимодействия
1. Streaming Service узнает у Сервера Прокторинга, куда транслировать медиапоток
2. Streaming Service осуществляет трансляцию в медиа-сервис (SFU)
3. Action Inspector Service отправляет фиксируемые события Серверу Прокторинга
4. Streaming Service осуществляет запись в локальное хранилище при недоступности Сервера Прокторинга
5. Action Inspector Service осуществляет запись событий в локальное хранилище при недоступности Сервера Прокторинга
6. Action Inspector Service и Streaming Service отправляют запрос на установление Websockets-соединения
7. Action Inspector Service и Streaming Service получают события из Websockets-соединения
8. Exam Service получает задания через запрос к основному Backend, который в свою очередь берет их из интегрированной LMS
#### Ответственные
За desktop-приложение отвественна команда разработчиков А, в частности Frontend Developers, Testers

### 4. Основное веб-приложение
#### Компоненты
1. React веб-приложение
#### Взаимодействия
1. Отправляет запросы Основному Backend для отображения курсов, заданий, расписаний
2. Отправляет запросы Основному Backend для публикации событий прокторинга
3. Отправляет запросы Основному Backend для осуществления апелляций
4. Отправляет запросы Основному Backend для аутентификации и авторизации
5. Отправляет запросы Основному Backend для изменения настроек прокторинга
6. Отправляет запросы Серверу Прокторинга для запроса медиа
7. Получает медиа от SFU
8. Отправляет запросы Серверу Прокторинга на установление Websockets-соединения
9. Получает события из Websockets-соединения
#### Ответственные
За основное веб-приложение отвественна команда разработчиков Б, в частности Frontend Developers, Testers
